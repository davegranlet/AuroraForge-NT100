### English SDB

`tools/append_2k25_sdb_string.js`

Observed format:

1. `u32` version (`256`)
2. `u32` record count
3. sorted 12-byte `(absolute offset, byte length, unsigned string ID)` records
4. null-terminated rolling-XOR UTF-8 strings

Cipher:

```text
firstKey = (absoluteOffset & 0xff) ^ 0xcd
cipher[0] = plain[0] ^ firstKey
cipher[n] = plain[n] ^ cipher[n - 1]
```

Current stock `ENG.sdb` has 96,477 records and ends at signed ID `-9555`.
`Draven` is the next ID, `-9554` / unsigned `4294957742`.

### SDB bug and correction

The first SDB appender incorrectly assumed a fixed first key of `0x31` because
that happened to be correct at TRIBUTE's older `Draven` offset.  Adding a table
record shifts every payload by 12 bytes, changing every first key.  The bad
build produced first-character corruption such as:

- `ATTENTION` → `STTENTION`
- `Unable` → `Inable`
- `DISMISS` → `PISMISS`
