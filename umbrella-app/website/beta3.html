THE PROBLEM

WWE 2K modding has become way too fragmented.

For too long, creators have been pushed into a workflow where one tool loads mods, another tool opens and bakes CAKs, another tool handles the creator workflow, and then everything still has to be staged, checked, launched, tested, and debugged by hand.

Worse, too much of that workflow has been wrapped in subscription-style access. The result is ugly: creators do the work, creators make the content, creators keep the scene alive, and then creators are told to keep paying every month just to keep using the pieces of the pipeline they already depend on.

That kind of setup works until something breaks. Then nobody knows whether the problem was the bake, the loader, the game update, the folder layout, the archive order, the texture path, the manifest, or the tool chain itself.

AuroraForge NT100 Beta 3 is built to end that mess.

This project exists because the community needs free alternatives to CakeHook-style loading, CakeView-style CAK work, and paywalled creator workflows. Not another permanent toll booth. Not another monthly pile-on. One 100% free package that covers the functions creators actually need and keeps moving toward public milestone releases.

THE NT100 APPROACH

AuroraForge NT100 is the bench.

Instead of asking users to assemble a stack of separate tools before they can even start modding, NT100 pulls the core workflow into one first-party app:

  • Secure DataCtrlLink handles the controlled loader path.
  • CAK Forge / Aurora CAK Foundry handles CAK viewing, extraction, baking, rebuilding, reopening, and verification.
  • 100% Not TRIBUTE is the complete feature-for-feature TRIBUTE replacement inside AuroraForge NT100.
  • The NT100 Creation Suite is Aurora's own higher-level creator workflow. It is the part nobody else has.
  • Texture tools, DDS conversion, PAC tools, animation conversion, logs, setup, and release tracking live beside the rest of the app instead of being scattered everywhere.

The point is not just convenience. The point is control.

When the app knows how the CAK was built, how it was staged, what the manifest says, which loader profile is being used, and what game version is being targeted, troubleshooting stops being a guessing game.

And when the tools are first-party, the workflow stops being hostage to three separate release cycles and three separate access gates.

LOADER

Secure DataCtrlLink

Secure DataCtrlLink is Aurora's controlled loader path.

It is built around game-version awareness, approved loading behavior, and a cleaner plugin path. The goal is not to blindly throw files at the game and hope they stick. The goal is to make mod loading predictable, testable, and easier to support when the game updates.

In normal user terms: this is the part that helps staged mod content actually get into the game.

CAK TOOLS

CAK Forge / Aurora CAK Foundry

CAK Forge and Aurora CAK Foundry handle the archive side of the workflow.

They are built for opening, extracting, baking, rebuilding, reopening, and verifying CAKs. That matters because a mod archive is not useful just because a tool says it was baked. It needs to reopen, validate, stage correctly, and behave in-game.

Aurora's CAK workflow is designed around that full loop:

prepare the folder → bake the CAK → verify the output → stage it → load it → test it.

CREATION SUITE

The NT100 Creation Suite.

The NT100 Creation Suite is Aurora's own higher-level workflow layer.

Do not confuse this with 100% Not TRIBUTE. 100% Not TRIBUTE is the complete feature-for-feature replacement for TRIBUTE inside AuroraForge NT100. The NT100 Creation Suite is the Aurora-first workflow layer built around where this project is going next.

This is where the app moves beyond "here is a file tool" and starts becoming a proper modding bench. The goal is to keep common creator tasks in one app instead of forcing users to jump between disconnected utilities for every step.

100% NOT TRIBUTE

100% Not TRIBUTE is the complete feature-for-feature replacement for TRIBUTE.

It lives inside AuroraForge NT100 instead of being a separate app users have to bolt onto the rest of the workflow. The point is direct: cover the same practical creator needs, make the flow easier to use, and keep it inside the same app as the loader, CAK tools, validators, logs, and release tracking.

The name is part of the point. It is not neutral. It is Aurora's answer to paid creator-workflow lock-in.

Texture replacement, attire work, character-slot workflows, project organization, setup, and release prep all belong in the same place.
